# 角色状态证据与回写规则

## 适用范围

`character-state` 只保存角色在当前时间线、基于已确认正文形成的动态状态。它回答
“角色现在是谁、经历了什么、知道什么、准备做什么”，不替代 `canon` 的稳定设定，
也不替代 `history` 的正式正文。

## 证据边界

只把以下内容视为状态更新证据：

- 用户确认采用的最终正文。
- 已写入并通过校验的当前状态和 change-log。
- 用户明确确认的长期设定或修正。

不要根据未来大纲、Ruler/Judgment 计划、未确认初稿、讨论中的假设或 Agent 推测
提前更新状态。正文没有表现、且不会影响后续连续性的临时细节也不要持久化。

## 唯一状态来源

创建或替换当前角色状态时，始终读取
`novel-rag/shared/templates/character-current.yaml`。提供模板要求的通用 metadata、
`metadata.character_id` 和 `metadata.variant_id`，并只沿用模板现有类型与以下
canonical 路径：

`character_state.current_position`、`physical`、`mental`、`knowledge`、`goals`、
`relationships`、`abilities`、`inventory`、`narrative`。

本引用不定义 YAML、字段别名或 change-log schema。写入前使用
`novel_rag.documents.load_document` 和 `validate_document` 验证从共享模板填充的
文档。

## 生成前读取

读取与当前任务有关的状态，不要把整部作品的状态无差别注入正文：

- 主视角角色：读取完整的 canonical 状态。
- 直接参与冲突的配角：读取其位置、身体/心理限制、知识、目标、关系和能力等
  canonical 字段中与场景有关的部分。
- 仅作背景的角色：只读取身份和当前行动所需的信息。

角色只能依据 `character_state.knowledge` 中的已知内容行动；未知内容不可被直接
使用，错误认知可以导致符合证据的误判。

## 更新触发

最终正文出现下列任一已证实变化时，才更新对应的 canonical 状态：

- 身份、阵营或当前位置改变。
- 伤势、疲劳、治疗、长期身体影响或能力代价改变。
- 情绪、压力、欲望、恐惧、未解决冲突或行为倾向改变。
- 新知识、误会解除、错误认知或仍未知的信息改变。
- 目标、优先级、阻碍或叙事承诺改变。
- 关系中的信任、态度、冲突、期待或重要事件改变。
- 能力可用性、消耗、限制、获得或失效改变。
- 物品携带、遗失或损坏改变。
- 当前角色弧线、已完成变化、未决标记或后续压力改变。

没有正文证据的长期成长、人格改写、能力升级、关系跃迁和秘密揭示不得写入。

## 变化证据与历史

不要直接抹掉旧状态。为每次持久变化保留章节、场景、角色、canonical 字段、变化
前后值和正文证据，以便追溯、审计和恢复。change-log 的具体存储格式由项目写入器
管理；本引用不另建格式。

## 冲突处理

发生冲突时按以下顺序裁决：

1. 用户当前明确修改。
2. 最新用户确认的正式正文（`history`）。
3. 该正文生成的、已通过校验的当前状态和 change-log。
4. 更早的状态或已废弃版本。
5. Agent 推测。

如果正文明确显示角色已获得某项知识，而旧状态仍标为未知，以正文为准并记录修正；
不得为了迁就旧状态改写正文。无法裁决的身份、胜负、能力、关系或世界规则保留为
待确认问题，不得自行补全。

## 审计

每次写回前检查：

- 时间线、位置、伤势、物品、能力消耗和关系是否连续。
- 行动是否符合 canonical 状态、已知信息、目标、压力和实际能力。
- 是否错误使用未知信息、提前揭示秘密或删除未解决矛盾。
- 变化是否有最终正文证据，是否把一次性情绪误写为永久状态。
- 是否只更新必要角色，且没有引入模板之外的字段。

## 确认与回写

用户确认最终正文后，按以下顺序回写：

1. 将正文写入 `history`，并完成其文档校验。
2. 从共享角色模板生成新 current 文档；校验后更新 `character-state/current`、
   snapshots 和 change-logs。
3. 从 `novel-rag/shared/templates/world-current.yaml` 生成并校验世界状态更新。
4. 将用户对正文的意见写入 `novel-rag/shared/templates/feedback.yaml`；规则、Canon
   或 Style Audit 的长期变更必须再次得到明确确认。

未确认正文、运行时摘要、Ruler/Judgment 结果和初稿都不得覆盖 current 状态。回写
完成后保留旧版本的可追溯关系，不把多个库的内容混装。
